# Roles MDM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Job posts point at admin-defined HIS business roles; roles apply Odoo groups to accounts and fill each till's list of names, so access comes from one master list.

**Architecture:** A new `his.role` model in `his_access_base` sits between `hr.job` and `res.groups`; the existing reconcile logic keeps working, fed by roles instead of raw groups. `his_stock_mdm` links roles to tills and derives the `pos_hr` lists from job posts. A data-only module `his_role_catalogue` ships the starting roles.

**Tech Stack:** Odoo 19 Community, Python, XML data, `odoo.tests.TransactionCase`.

**Spec:** `docs/superpowers/specs/2026-10-27-roles-mdm-design.md`

## Global Constraints

- Source strings in English; every new term gets its French in the module's `i18n/fr.po` (test `test_chaque_terme_a_sa_traduction_francaise`, which also wants the model name of each new `_inherit` and labels of redeclared fields). Add entries by hand, then check with `odoo i18n export` on a database with the CI's modules that no existing msgid disappeared.
- Menu groups: `(4, …)` / `(3, …)` only, never `(6, 0, …)`.
- No ACL line may grant a business model to `base.group_user` (`test_aucun_modele_metier_ouvert_a_tout_le_monde`).
- Sensitive groups (never through a post or a role), exactly: `base.group_system`, `base.group_erp_manager`, `base.group_sanitize_override`, `mail.group_mail_template_editor`, `account.group_account_manager`, `base.group_allow_export`, `api_doc.group_allow_doc`. Missing xmlids (module not installed) are skipped.
- Only `base.group_erp_manager` writes roles, a post's roles, account types and account roles.
- Beta modules untouched: `his_crm_pipeline`, `his_admission`, `campus_teacher_management`, `campus_identity_bridge`, `insite_recruitment`. Abdo's `maintenance_university` and `his_hygiene`: not touched.
- Commits: `git -c user.name=Endeavor -c user.email=mohamed.bounouaa@outlook.com commit …`, no `Co-Authored-By` trailer.
- Before pushing: `ruff check .`, `ruff format --check .` (whole repo, it formats the `.md` files too), `pylint --rcfile=.pylintrc <modules>`.

## How to run tests locally

The dev container mounts the main checkout at `/mnt/extra-addons`, so this worktree is `/mnt/extra-addons/.worktrees/roles-mdm`. Run from **PowerShell** (Git Bash rewrites `/etc/...` paths). Make a throwaway copy of the local `ci` database once:

```powershell
docker exec his-odoo-addons-db-1 createdb -U odoo -T ci roles_ci
```

Then, for module `M` and test class `C`:

```powershell
docker exec his-odoo-addons-odoo-1 odoo -c /etc/odoo/odoo.conf --http-port 8070 --stop-after-init `
  --addons-path=/usr/lib/python3/dist-packages/odoo/addons,/mnt/extra-addons/.worktrees/roles-mdm `
  -d roles_ci -u M --test-tags /M:C
```

Pass: log ends with `0 failed, 0 error(s)`. Use `-i` instead of `-u` the first time a module is installed.

## Review Focus

1. **A till that has cashier roles but nobody eligible** (no holder, or no holder with a PIN) must not fall back to "everyone may tap in": it shows only POS managers. Test: Task 4 `test_till_with_roles_but_no_eligible_cashier_is_closed`.
2. **A cashier who changes post or loses their PIN** must disappear from the till at once, not at the next cron. Test: Task 4 `test_losing_pin_or_post_removes_from_till`.
3. **A role edited after people already hold it** (group removed) must remove the group from everyone, while their hand-added exceptions survive. Test: Task 2 `test_removing_a_group_from_a_role_removes_it_from_holders_only`.
4. **A sensitive group reached through implication** (a harmless-looking group that implies `base.group_allow_export`) must be refused on a role. Test: Task 1 `test_role_refuses_group_implying_sensitive`.
5. **An HR officer** (not admin) editing a job post or an employee must not be able to set roles, yet changing an employee's post must still re-apply roles (sync runs in sudo). Test: Task 2 `test_hr_officer_cannot_set_post_roles_but_moves_people`.
